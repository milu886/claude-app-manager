# 1.0.4 · 下载与安装提速

参考 Codex App Manager 的下载流程（断点续传、失败重试、停滞检测），并按本机实测结果进一步优化。

## 下载

- 多连接分段下载：默认 6 个连接、8 MB 分段。实测经系统代理：GitHub 单连接 1.65 MB/s、4 连接 3.86 MB/s、8 连接 5.35 MB/s；镜像单连接 3.26 MB/s、4 连接 6.03 MB/s。
- 多来源同时下载：镜像（版本一致时）、Anthropic 官方 CDN 固定版本地址（取自镜像清单或 GitHub 发布中的 `release-manifest.json`，且版本、SHA-256、大小必须一致）与 GitHub 共同分担，按实测速度分配分段；连续失败或内容不一致的来源会被停用。“仅 GitHub”模式只使用 GitHub。
- 断点续传：网络中断时保留已完成的分段（`.part` 与进度记录），重试从剩余分段继续；用户取消仍会清除部分文件。
- 停滞检测：连接 30 秒没有收到数据即放弃并重新分配该分段；单连接回退路径同样适用（原先只有 30 分钟总超时）。
- 镜像 `/latest` 在下载中途切换版本导致校验失败时，自动改用固定版本来源重下。最终仍须通过完整 SHA-256 校验。
- 实测：Claude `4.4212.0` x64（283,055,488 字节）经代理 47.8 秒下载完成，平均 5.65 MB/s，官方 CDN 与 GitHub 同时使用；此前单连接约 13 分钟。

## 安装

- 下载校验后立即预安装（`Add-AppxPackage -Stage`，验证签名后执行，不影响正在运行的 Claude）。Windows 部署日志显示新版本解包耗时 37–83 秒，预安装后注册约 1 秒。预安装失败不影响下载结果，安装时会重新解包。
- 状态检测从约 3.3 秒降到约 1 秒：改用程序包标识（`GetPackageFamilyName`）识别 Claude 进程，不再逐个读取所有进程路径；安装完成后直接复用安装脚本返回的状态，不再额外检测。
- 识别由 Claude 启动、仍带有 Claude 程序包标识的其他程序（实际案例：一个 `java.exe` 测试服务，使 Windows 在强制更新时等待约 90 秒后才结束它，并导致此前多次更新被延后）。“完成更新”前列出这些程序，经你确认后按 PID 关闭（仍须带有 Claude 标识）；取消则不做任何更改。自动安装从不关闭这些程序。
- 不再按进程名 `claude.exe` 判断桌面端是否运行，避免独立安装的 Claude Code CLI 被误判为 Claude 桌面端。
- PowerShell 脚本改经标准输入传递（Base64），不再受 `-EncodedCommand` 32K 命令行长度限制。

## 验证

- 61 项测试：新增多来源并行下载、失败来源停用、断点续传、停滞重试、`/latest` 变化回退、取消清理、无 Range 回退、官方 CDN 地址校验、预安装及其失败、遗留程序确认流程、进程分类与真实标识探测。
- 打包程序冒烟测试通过。“完成更新”的预安装与关闭遗留程序流程需在下一个 Claude 新版本发布时实际验证。
